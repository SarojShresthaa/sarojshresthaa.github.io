# Portfolio CMS setup (GitHub Pages)

This site uses **only a custom Umbraco 17–inspired backoffice** at **`/cms/`**. It is not the official Umbraco CMS and does not use Decap or any other third-party CMS product.

## Architecture

| Layer | Role |
|--------|------|
| `content/**/*.json` | Source of truth for portfolio copy, projects, settings |
| `js/portfolio.js` | Public site: loads JSON and renders into existing HTML shells |
| `/cms/` | Custom backoffice (tree, editors, media, save/publish) |
| GitHub Pages | Serves static files only |

## Public URLs

GitHub Pages serves extensionless URLs for `.html` files (e.g. `/projects` → `projects.html`). Project details use `/projects/{slug}/` via `projects/{slug}/index.html`.

## Editing content

### Custom CMS (`/cms/`)

1. Edit **`cms/config.public.json`** (committed to the repo): set `oauth_proxy_url` and `github_client_id` from your GitHub OAuth app.
2. Create a **GitHub OAuth App** (callback URL must match your OAuth proxy — see below).
3. Deploy a small **GitHub OAuth proxy** (e.g. [decap-cms-github-backend](https://github.com/decaporg/decap-cms-github-backend) on Render). Put the **client secret** only on the proxy, never in this repo.
4. Push to GitHub and open **`https://sarojshrestha.me/cms/`** — use **Sign in with GitHub** in the top toolbar, then **Save** or **Publish**.

**Security:** Never commit personal access tokens or OAuth **client secrets**. Only the public Client ID and proxy URL go in `config.public.json`.

Until OAuth is configured, **Sign in with GitHub** appears but is disabled; you can still edit in the UI and save via git by editing `content/` JSON files.

## CMS username / password gate

Optional extra lock on `/cms/` before the backoffice loads (separate from GitHub sign-in for Save).

1. Choose a password and generate a SHA-256 hash locally (never commit the plain password):

   ```bash
   node scripts/hash-cms-password.js "your-strong-password"
   ```

2. In `cms/config.public.json`, set `cmsAccess`:

   ```json
   "cmsAccess": {
     "username": "saroj",
     "passwordSha256": "<paste hash here>",
     "sessionHours": 12
   }
   ```

3. Push to GitHub. Visiting `/cms/` shows a login form first; **Lock** in the toolbar ends the session.

**Note:** On static GitHub Pages this is a **browser gate** (hash in public config). It keeps casual visitors out but is not as strong as server-side auth (e.g. Cloudflare Access). GitHub sign-in is still required to **Save** to the repository.

### Local git

You can edit JSON under `content/` directly and push to `main`; GitHub Pages redeploys automatically.

## Draft vs published

Documents include `"status": "published"` or `"draft"`. The public site skips draft content where enforced (e.g. projects list).

## Adding a project

In `/cms/`: **New project** → fill fields → **Save**. This commits:

- `content/projects/{slug}.json`
- `projects/{slug}/index.html` (detail route)
- Updates `content/projects/index.json` `slugs` array

## Images

- Existing images: `img/`
- Media index: `content/media/index.json`
- Upload in CMS **Media** section (requires GitHub sign-in)

## Limitations (GitHub Pages)

- No server-side validation or real Umbraco features
- Saves are **git commits**; live site updates after Pages build (~1–2 minutes)
- Browser cannot push to GitHub without OAuth + proxy (or manual git)
- Project detail routes require a static `index.html` per slug (generated by CMS on save)

## Maintenance

- Navigation: `content/site-settings.json` → `navigation`
- Featured home projects: `content/home.json` → `featuredProjectSlugs`
- Project order: `content/projects/index.json` → `slugs`
- **Public site:** only projects with `status: "published"` appear on `/projects`. New projects start as **Draft** — use **Save** then **Publish** in the CMS (GitHub sign-in required).
- **Recycle bin:** deleted projects are stored in `content/recycle-bin/index.json` (restore or purge from the 🗑 section in the CMS).
- **Custom pages:** **New page** in the CMS → `content/pages/{slug}.json` + `{slug}.html` at repo root. Optional **Show in nav** updates `site-settings.json` navigation.
- **Images:** use **Choose…** on image fields (Home, Projects, custom pages) to pick from the media library; upload new files under **Media** (🖼).
- **List pages** (Experience, Education, Skills, Services, Certifications) use visual repeaters instead of raw JSON.
